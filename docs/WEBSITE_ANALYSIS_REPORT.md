# GIGATECH 홈페이지 신규 구축 사전 분석 보고서

분석일: 2026-09-26 · 범위: 자료 조사, 메뉴·콘텐츠·자산 분석, 구축 계획 제안

## 1. 결론

기존 홈페이지를 수정할 수 있는 소스코드나 서비스 환경은 이 작업 폴더에서 발견되지 않았다. **사용자가 지정한 메뉴 엑셀을 기준으로 홈페이지를 새로 설계·구현하고, 기존 자료는 검증 후 콘텐츠로 활용하는 작업**이다.

지정된 `페이지 메뉴 구성안.xlsx`는 **대메뉴 3개, 하위 페이지 5개**다. 홈을 별도로 구성하면 기본 제작 범위는 **홈 + 상세 5페이지**가 된다. 홈 구성과 경로는 제안이며 엑셀에 없는 메뉴를 확정한 것이 아니다.

현재 자료만으로 화면 설계와 콘텐츠 초안 작성은 시작할 수 있다. 다만 **인증서 원본, 정보통신설비 사업의 회사별 자료, 실제 장비 목록, 현재 회사 정보**가 부족해 전체 내용을 곧바로 공개할 상태는 아니다.

## 2. 실제 메뉴와 자료 대응

기준 원본: `docs/1.홈페이지 제작관련/페이지 메뉴 구성안.xlsx`. 정확한 셀·보조 문서 비교는 [메뉴·콘텐츠 분석](analysis/MENU_CONTENT_AUDIT.md)을 참조한다.

| 대메뉴 | 하위 페이지 | 내부 자료 상태 | 확보된 자료 | 필요한 제작·보완 |
| --- | --- | --- | --- | --- |
| 회사소개 | 인사말 | 부분 확보 | `내부내용자료/인사말.txt`, 로고, 조직도 PPTX | 기계설비 중심의 인사말을 두 사업을 소개하는 문안으로 정리. 회사의 현재 소개·대표 표기 확인. 조직도는 본문 활용 후보 |
| 회사소개 | 인증서 | 누락 | 메뉴 이름만 존재. 실제 인증서·등록증 이미지 미발견 | 회사의 유효한 인증서/등록증 원본과 공개 범위 확보. 외부 검색으로 유사 업체의 인증서를 대신 사용하지 않음 |
| 주요업무 | 기계설비 성능점검 | 부분 확보 | 기계설비 개요·점검 절차·검토사항·점검 이미지, 관리주체 관련 참고자료 | 본문과 표·절차를 웹 문서로 새로 구성. 회사 실제 업무와 현행 기준 확인. 타사 문구·워터마크가 있는 이미지 재사용 제외 |
| 주요업무 | 정보통신설비 성능점검 | 내부 전용 자료 누락 | 지정 메뉴 E8. 일반 설명을 작성할 국가법령정보센터 공식 자료는 외부에서 확인 | 서비스 범위·점검 절차·결과물 설명 신규 작성. 회사의 수행 자격·전문 인력·장비·현장 사진·실적 확보 |
| 장비보유현황 | 점검장비 | 부분 확보 | 장비 목록 이미지 4파일 중 1쌍 완전 중복 | 이미지의 장비명 정리, 실제 보유 여부·모델·수량·교정 관련 정보 확인. 목록 카드로 재구성하고 필요 사진 보완 |

공통 로고와 인사말 등 활용 가능한 자료는 있으나, 제공 파일의 존재가 현재 사실·소유권·게시 승인까지 증명하지는 않는다. 확인되지 않은 회사 자격·실적·수량을 임의로 작성하지 않는다.

## 3. 메뉴가 서로 다른 이유와 적용 원칙

`디자인중.xlsx`에는 6개 대메뉴와 13개 하위 항목이 있고, 별도 예시 엑셀과 수정 요청 텍스트도 있다. 이 파일들은 사용자가 지정한 기준안과 범위가 다르다.

- 기준안의 정보통신설비 성능점검은 별도 확장안에 없는 중요한 항목이다.
- 기계설비법 별도 메뉴, 고객문의·견적문의, 카카오·온라인 채팅, 게시판 등은 보조 자료에 나타난다. 이번 기본 범위에 자동 추가하지 않는다.
- 기준안의 저장 메타데이터는 2026년, 디자인중·예시는 2023년이지만 저장일만으로 승인 이력 전체를 확정하지 않는다. **지정된 파일을 우선한다는 사용자 요청**을 기준으로 한다.
- 메뉴 밖의 조직도·기계설비 개요·절차는 관련 페이지의 본문 재료로 활용할 수 있다.

## 4. 자산 조사에서 발견한 문제

원본 폴더는 총 **58파일**이다. `desktop.ini` 9개와 Excel 잠금파일 1개를 제외하면 48개이며, 여기에도 압축·중복·참고자료가 포함된다. 파일별 경로·크기·SHA-256은 [원본 목록](analysis/SOURCE_INVENTORY.json)에 기록했다.

- 독립 이미지 30파일, ZIP 7개, PPTX 2개, 유효 XLSX 3개, TXT 4개, PDF/HWP 각 1개가 있다.
- ZIP에는 이미 풀린 자료와 같은 이미지가 들어 있다. 압축을 더 풀어도 없는 인증서나 정보통신 전용 사진이 생기는 구조가 아니다.
- `장비사진3.png`와 `장비사진4.png`는 바이트 단위로 같다.
- 기계설비 검토사항 이미지에 **에이엠이엔지**라는 다른 업체명이 있고, 법 위반 안내 이미지에는 **KMEM** 워터마크가 있다. 신규 사이트의 회사 설명으로 그대로 게시해서는 안 되는 참고자료다.
- 로고는 활용 후보이나 벡터 원본은 확인되지 않았다. 여러 설비 사진은 작은 크기여서 대형 메인 이미지로 확대하기 어렵다.
- 표·법령·절차를 캡처한 이미지는 모바일 가독성·검색·접근성을 위해 텍스트와 표로 재작성하는 것이 적절하다.
- 장비 목록 이미지는 회사의 현재 장비 보유 증빙으로 충분하지 않다.
- 조직도는 내용이 다른 2개 버전이며 템플릿 회사명 `CONTOSO`가 남아 있어 현재 조직 확인과 정리가 필요하다.
- 장비 폴더에 섞인 PDF/HWP는 대학·호텔 등의 채용 참고자료로 확인됐다. 자사 인증·회사 소개의 근거로 사용할 수 없다.

전체 이미지의 실제 열람, 문서·압축 비교와 활용 판단은 [자산 분석](analysis/ASSET_AUDIT.md)에 기록한다.

## 5. 외부에서 찾은 자료와 확인 한계

정보통신설비 페이지의 일반 설명을 작성할 자료는 확보 경로가 있다. 국가법령정보센터의 [설비 대상 현황표 PDF](https://www.law.go.kr/flDownload.do?bylClsCd=200203&flNm=%5B%EB%B3%84%EC%A7%80+1%5D+%EC%A0%95%EB%B3%B4%ED%86%B5%EC%8B%A0%EC%84%A4%EB%B9%84+%EC%9C%A0%EC%A7%80%EB%B3%B4%EC%88%98%C2%B7%EA%B4%80%EB%A6%AC+%EB%B0%8F+%EC%84%B1%EB%8A%A5%EC%A0%90%EA%B2%80+%EB%8C%80%EC%83%81+%ED%98%84%ED%99%A9%ED%91%9C&flSeq=154578187)와 [성능점검 검토사항 PDF](https://www.law.go.kr/LSW/flDownload.do?bylClsCd=200201&flNm=%5B%EB%B3%84%ED%91%9C+2%5D+%EC%A0%95%EB%B3%B4%ED%86%B5%EC%8B%A0%EC%84%A4%EB%B9%84+%EC%84%B1%EB%8A%A5%EC%A0%90%EA%B2%80+%EA%B2%80%ED%86%A0%EC%82%AC%ED%95%AD%28%EC%A0%9C10%EC%A1%B0%EC%A0%9C1%ED%95%AD+%EA%B4%80%EB%A0%A8%29&flSeq=154578419)는 원문 텍스트를 확인했다. 이 자료는 업종 설명의 근거이며 회사의 수행 범위를 증명하지 않는다.

[부천시청 공개 게시물](https://www.bucheon.go.kr/site/program/board/basicboard/view?boardtypeid=27552&encid=hXLeN87QyGkSkVgIf3Pg5Q%3D%3D&menuid=148006004012009&pagesize=10) 검색 결과에서 두 성능점검 사업을 소개하는 기가테크와 `지명원.pdf` 첨부 표시를 발견했다. **동일 법인 여부와 첨부 내용은 미확인**이다. 소개서를 확보하면 인증서·실적·회사 소개를 보완할 가능성이 있다.

내부 기록의 기존 도메인 `gigatech.kr`은 이번 도구에서 사이트 본문을 가져오지 못했다. 카카오 채널 URL에서는 `주식회사 기가테크`라는 페이지 제목을 확인했다. 이를 도메인 소유권 확인이나 상담 정상 동작 검증으로 보지 않는다. 과거 아카이브도 이번 조사에서 확보하지 못했다.

법령·대상 건축물·점검 주기·과태료를 게시할 때는 현재 시행본과 향후 시행 개정본을 구분해야 한다. 과거 캡처 문구를 그대로 옮기지 않는다. 상세 출처와 검색·접근 실패 기록은 [외부 조사 기록](analysis/main/EXTERNAL_RESEARCH.md)에 있다.

## 6. 신규 사이트의 권장 구성

**기본안은 회사 소개와 두 사업 안내에 집중하는 반응형 사이트**다. 첫 화면에서 기계설비/정보통신설비 사업을 구분하고, 인증·장비 등 확인된 근거와 상담 동선으로 이어지게 한다. 메인 비주얼은 기존의 작은 설명용 사진보다 사용 권한이 확인된 현장 사진 또는 별도로 제작한 그래픽이 적합하다.

| 구분 | 기본 제작안 | 별도 선택 시 추가 작업 |
| --- | --- | --- |
| 화면 | 홈, 상세 5페이지, 모바일 메뉴, 공통 회사 정보·연락처 | 고객문의·견적 페이지, 자료실/게시판 |
| 콘텐츠 | 확인된 회사 정보, 두 사업 소개, 인증서, 장비 목록 | 실적, 뉴스, 채용, 다국어 등은 요청 시 검토 |
| 상담 | 현재 운영 확인 후 전화·이메일·카카오 링크 | 사이트 내 문의/견적 접수, 첨부파일, 접수 알림 |
| 운영 | 콘텐츠 파일 수정 후 재배포 | 비개발자 직접 수정이 필요하면 CMS·관리자 도입 검토 |
| 서버·DB·인증 | 기본 소개형은 자체 서버·DB·회원가입이 필수 아님 | 접수 보관·첨부·관리자 운영 방식을 정한 뒤 필요한 부분 설계 |
| 품질 | 검색 가능한 본문, 모바일 가독성, 키보드 접근, 메타정보, HTTPS, 링크 확인 | 실제 접수 기능을 채택하면 보안·개인정보·실패 처리 검증 추가 |

기존 기술 스택 설정과 제품 코드가 없어 스택은 아직 미정이다. 상세 대안은 [기능·기술 분석](analysis/BUILD_REQUIREMENTS.md)에 제안으로 기록한다. 디자인 시안·API·DB 계약이 확정되기 전 특정 기술이나 전체 기능을 완료 상태로 취급하지 않는다.

## 8. 실행과 검증 범위

메인 PM과 별도로 **pm(메뉴·콘텐츠), designer(자산), architect(기능·기술)** 세 에이전트가 실제로 독립 분석했다. 메인은 원본 목록·외부 조사·최종 계획·상태를 통합한다.

이번 산출물은 분석 문서와 그 근거다. 앱 구현·의존성 설치·서비스 배포·운영 계정 변경·메시지 발송은 수행하지 않았다. 제품 코드가 없어 빌드/단위/E2E 검사를 실행하거나 통과한 것으로 기록하지 않는다. 문서·원본 보존 검증 결과와 역할별 실제 완료 상태는 [TEAM_STATUS](TEAM_STATUS.md)에 기록한다.

후속 역할별 소유권과 완료 기준은 [TEAM_PLAN](TEAM_PLAN.md), 상세 내용은 다음 문서에 있다.
