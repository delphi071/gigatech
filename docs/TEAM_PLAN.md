# GIGATECH 홈페이지 신규 구축 분석 계획

- 요청 범위: 기존 홈페이지의 잔존 자료와 메뉴 엑셀을 분석하고 신규 구축에 필요한 작업을 보고한다.
- 현재 단계: 0 자료 확인 → 1 요구사항 분석·계획. 제품 구현·설치·배포는 이번 작업 범위 밖이다.
- 원본 입력: `docs/1.홈페이지 제작관련/` 전체. 원본과 `.claude`, `.codex`, `.agents` 설정을 보존한다.
- 기준 메뉴: `docs/1.홈페이지 제작관련/페이지 메뉴 구성안.xlsx`. 예시·디자인중 파일은 별도 보조 자료로 구분한다.
- 기존 제품 코드, `docs/TECH_STACK_CONFIG.md`, 기존 TEAM 문서는 최초 목록 조사에서 발견되지 않았다. 기술 스택은 분석 후 제안으로만 기록한다.

## 자료 취급 및 검증

- 원본은 읽기만 하고 추출·파생 자료는 각 담당 하위 경로에 저장한다.
- 실제 실행한 파싱·파일 검사·이미지 열람·공식 출처 확인만 보고한다. 검사 불가 파일과 검색 실패도 명시한다.
- 회사명·연락처·서비스 문구는 출처를 연결한다. 추정한 사실, 과거 법령·기준을 현재 사실로 단정하지 않는다.
- 외부 확인이 필요한 법령·공식 정보는 공식 원문을 확인하거나 최신 확인 필요로 남긴다.
- 문서에 비밀번호·접속 토큰이 있을 경우 값은 출력·복제·보고하지 않는다.
- 소프트웨어 테스트는 제품 코드가 없으므로 현재 단계 대상이 아니다. 분석 검증과 구현 검증의 상태를 구분한다.

## 후속 단계의 진입 조건

1. 메뉴와 페이지별 콘텐츠, 견적/문의 접수·게시판 운영 범위를 정리한다.
2. 현재 회사 정보·자료 사용 권한·운영 방식 등 제작을 막는 결정을 확인한다.
3. 기술·디자인 설계에서 스택, URL, 폼 계약과 필요한 경우 DB 계약을 확정한다.
4. 메인만 공유 패키지·잠금·설정을 관리하고, 프론트/서버/DB 실제 경로와 담당을 확정한 후 구현한다.
5. QA → 테스트·감사 → 요청된 배포 순으로 진행한다. 현재 분석 보고서가 구현 검증 통과를 의미하지 않는다.

## 분석으로 정리한 범위

- 사용자 지정 기준안: 회사소개(인사말, 인증서), 주요업무(기계설비 성능점검, 정보통신설비 성능점검), 장비보유현황(점검장비).
- 홈 + 5개 상세 페이지와 공통 연락 동선을 기본 제작안으로 제안한다. 독립 URL과 상위 메뉴 클릭 동작은 설계 단계에서 확정한다.
- 디자인중 엑셀의 추가 메뉴, 문의/견적 접수, 게시판·관리자·CMS·다국어는 기본 범위에 자동 포함하지 않는다.
- 소개형 기본안은 자체 서버/DB/회원가입이 필수 아니다. 정적 사이트를 우선 검토하고 실제 접수·편집 운영 요구가 정해지면 확장한다.
- 정보통신설비 일반 내용은 공식 자료로 작성할 수 있으나 회사의 수행 자격·인력·실적·인증은 회사별 근거가 필요하다.
- 회사명·주소·연락처, 인증서, 실제 장비, 정보통신 사업자료가 공개 콘텐츠 확정에 필요하다. 미확정 정보가 있어도 내부 화면·콘텐츠 초안은 준비할 수 있다.

## 후속 소유권과 단계 편성

1. 메인 PM은 `TEAM_PLAN`, `TEAM_STATUS`, 콘텐츠 범위와 공유 설정을 소유한다. 역할 보고서의 확정 여부를 먼저 검토한다.
2. designer는 제공 원본과 신규 화면 설계에 근거한 `docs/TEAM_DESIGN_SPEC.md`, architect는 `docs/TEAM_TECH_SPEC.md`를 작성한다. 현재 분석 보고서를 완성된 디자인/기술 계약으로 대신하지 않는다.
3. 자체 저장을 선택하면 dba가 `docs/TEAM_DB_SCHEMA.md` 및 단독 지정 ORM 경로를 소유한다. 정적 소개형이면 DBA/backend 단계 해당 없음 사유를 기록한다.
4. 스택과 디렉터리가 확정된 뒤 메인이 초기 구성·의존성을 단독 처리하고 frontend/backend/dba의 실제 구현 경로를 이 계획에 추가한다. 아직 존재하지 않는 코드 경로를 확정된 사실로 기록하지 않는다.
5. 설계 완료 후 필요한 구현 역할만 병렬 진행하고, QA 이후 tester+auditor를 병렬 진행한다. QA·감사 담당의 애플리케이션 코드 수정은 별도 소유권 이전 후에만 허용한다.

분석 산출물과 검증 근거는 `docs/WEBSITE_ANALYSIS_REPORT.md`, 역할별 `docs/analysis/*_AUDIT.md` 및 `BUILD_REQUIREMENTS.md`에 연결한다. 이 계획은 신규 구현 또는 production 배포 승인을 받은 것으로 해석하지 않는다.
